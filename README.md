# Trae 多账号冷切换助手（Trae-Switch）
> 作者：**星梦**
一个用于在 **TRAE** 多个账号之间「冷切换」的 Windows 桌面小工具。先为每个账号建档一份登录态备份，之后无需验证码即可一键切换到目标账号，并内置「切换守护」在切换失败时自动回滚。

## 功能特性
- **多账号建档**：为每个账号备份一份登录态（`vault`），只对“随账号切换而变化”的载体文件做字节备份。
- **自动识别当前登录账号**：客户端退出后，通过判别文件哈希自动识别当前会话属于哪个账号，并在列表中标为「当前账号 ✓」。
- **一键冷切换**：选中目标账号后一键完成：结束客户端 → 写回目标账号登录态 → 重新启动，**免验证码进入**。
- **切换守护**：切换后轮询客户端登录会话写入，自动判定 Active / RolledBack / NeedsConfirm；判定失败时自动回滚到切换前的账号并重启。
- **快照自动刷新**：客户端退出后，工具会静默用当前有效会话刷新该账号的备份（内容确有变化才更新），让备份保持“新鲜”。
- **建档即校验**：建档后立即校验，回显载体文件数，确保备份可恢复。
- **单实例运行**：仅允许启动一个实例，再次双击会自动唤起已运行的窗口。
- **单元测试**：核心逻辑（守护判定、凭据探测、判别集、载体指纹）带单元测试，保证切换可靠性。

## 程序运行原理
程序是一个 **C# WinForms** 桌面应用（.NET 9），运行流程如下：
```
┌─────────────────────────────────────────────────────────────┐
│                        建档（每个账号一次）                    │
│  确认客户端登录该账号 → 结束客户端（解除登录态文件占用）        │
│  → 自动识别当前账号 → 备份载体文件到 vault\<账号>\           │
└──────────────────────────────┬──────────────────────────────┘
                               ▼
┌─────────────────────────────────────────────────────────────┐
│                        一键切换目标账号                       │
│  结束客户端 → 把当前 live 快照到临时回滚区 →                  │
│  写回目标账号 vault → 拉起客户端                            │
└──────────────────────────────┬──────────────────────────────┘
                               ▼
┌─────────────────────────────────────────────────────────────┐
│                         切换守护                             │
│  轮询 storage.json 会话写入（最长 20 秒）：                  │
│  ├─ 写入过 + 凭据齐全 ──► Active（已进入目标账号）            │
│  ├─ 凭据缺失/未起来 ──► RolledBack（自动回滚并重启）          │
│  └─ 信号不足 ────────► NeedsConfirm（弹窗让用户确认）         │
└─────────────────────────────────────────────────────────────┘
```
核心组件：
| 文件 | 作用 |
|------|------|
| `Program.cs` | 程序入口、单实例互斥锁、窗口唤起 |
| `MainForm.cs` | 主界面、一键建档/切换、自动识别、快照自动刷新 |
| `Services/VaultService.cs` | 账号登录态按“载体”字节备份、恢复、判别文件识别 |
| `Services/SwitcherService.cs` | 冷切换编排 + 切换守护（Active/RolledBack/NeedsConfirm） |
| `Services/AuthProbe.cs` | 登录凭据键探测、会话写入判定（只读，不会误回滚） |
| `Services/CarrierProfiler.cs` | 载体目录哈希指纹与 diff |
| `Services/ClientController.cs` | 按进程名结束/启动客户端 |
| `Services/SettingsStore.cs` | 本地配置 `settings.json` 读写 |
| `TraeSwitch.Probe` | Phase 0 载体定位脚本（找出随账号切换而变化的文件） |
| `TraeSwitch.Tests` | 单元测试（守护四态、凭据探测、判别集、指纹） |

## 切换原理
TRAE 客户端的帐号登录态保存在本地文件（`User\globalStorage\storage.json`、LevelDB 等）。`VaultService` 只对这些“随账号切换而变化”的载体做字节备份到 `<vault>\<账号>\`；切换时整体写回 live 目录。
**自动身份识别**（`VaultService`）：计算“判别文件”集合——跨账号哈希互不相同或仅部分账号拥有的载体文件，用它来给 live 计算相似度，避免共享文件把分数拉向中间、降低区分度。同机共享、每次运行都改写的 noise/运行痕迹文件（如 LevelDB 的 LOG、config.db）会被剔除，保证识别稳定。
**切换守护**（`SwitcherService.SwitchWithGuardAsync`）：
1. 结束客户端进程，并把当前 live 快照到临时回滚区。
2. 写回目标账号 vault，拉起客户端。
3. 最多等待 20 秒，轮询 `storage.json` 是否被写入过（云会话在工作）。
4. 依据“是否写入 + 凭据是否齐全”判定 Active / RolledBack / NeedsConfirm，失败时自动回滚并重启。
> 注意：需要先在该账号上**登录一次并建档**，才能对它免验证码切换；退出的会话凭据长期有效（周级），快照自动刷新可保持其新鲜。

## 使用说明
### 运行环境
- Windows 10 / 11（TRAE SOLO CN 客户端已安装）
- [.NET 9 运行时](https://dotnet.microsoft.com/download)（或使用已发布的可执行文件）
### 首次使用
1. 登录账号 A，点「建档（自动识别+一键）」，确认后自动退出客户端并建档。
2. 切到账号 B 登录，同样点一次「建档」。
3. 在列表中选中要切换到的账号，点「切换到选中账号」即完成冷切换。
4. 切换后确认已进入目标账号即可正常使用；退出客户端时点「刷新列表」，工具会自动用当前会话刷新该账号备份。
### 载体定位（Phase 0，仅首次配置）
默认指纹可能不覆盖你的客户端版本。可先运行 `TraeSwitch.Probe`，在“登录前/登录后”各扫一次目录指纹，把 diff 出的变化相对路径填到 `settings.json` 的 `Fingerprint` 列表中，再行建档。
### 构建
```bash
# 编译主程序（输出到 bin\TraeSwitch\）
dotnet build TraeSwitch.csproj -c Release
# 跑单元测试
dotnet test TraeSwitch.Tests\TraeSwitch.Tests.csproj
```

## 配置文件位置
| 内容 | 路径 |
|------|------|
| 配置（账号列表、客户端路径、载体指纹） | `%APPDATA%\TraeSwitch\settings.json` |
| 各账号登录态备份（vault） | `%LOCALAPPDATA%\TraeSwitch\vault\<账号>\` |
> ⚠️ **安全提示**：`vault` 中保存着各账号的登录态字节（等同登录凭证），极其敏感。请勿将 `vault` 目录或包含登录态的文件提交到任何公开仓库或分享给他人。
