# 设计文档：TraeSwitch —— TraeWork CN 多账号冷切换助手

- 日期：2026-09-05
- 状态：待评审
- 形态：独立 WinForms / .NET 9 小工具（新建独立仓库目录 `TraeSwitch`，不并入 TraeCheckin）

## 1. 背景与目标

TraeWork CN 桌面客户端（进程名 `TRAE SOLO CN.exe`，窗口名 "TraeWork CN"，安装于
`D:\TRAE SOLO CN\`，用户数据在 `%APPDATA%\TRAE SOLO CN\`）同一时间只能登录一个账号。
切换账号时，客户端要求先退出当前账号，再走"网页 → 手机号验证码 → 授权回客户端"的完整
流程。用户手上有 2 个常用账号、目标使用场景 3-4 个，每次切换都要重新输一次手机验证码，
非常繁琐。

目标：让客户端记住每个账号的"登录态"，此后切换 = 一键执行
`退出当前账号登录态 → 恢复目标账号登录态 → 重开客户端`，全程不再要求手机验证码。

边界（用户明确）：只操作"登录态存储"，不改客户端、不模拟网络登录、不伪造请求、
不抓取/解密 token 内容、不复制对话/任务内容。

## 2. 非目标

- 不做对话/任务/进度迁移（由独立工具 ProjectHandoff 承担）。
- 不模拟网页授权流程，也不把预存 Cookie 走网络流程换桌面 token。
- 不支持"客户端不退出、界面内热切换身份"（受客户端单账号限制）。
- 不做多账号同开（同时运行两个客户端实例）。

## 3. 目标客户端现状（已探明）

- 产品：TraeWork（原 TRAE SOLO），中文桌面端窗口名 "TraeWork CN"。
- 进程/安装：`D:\TRAE SOLO CN\TRAE SOLO CN.exe`（Electron 系，含 `resources\app\modules\ai-agent`）。
- 用户数据目录：`%APPDATA%\TRAE SOLO CN\`，含 Chromium 结构
  （`Local Storage`、`Network`、`Cache`、`IndexedDB`、`Session Storage`…），
  以及字节系目录 `aha\`、`ahanet\`、`ModularData\`、`machineid`、`Local State`、`Preferences` 等。
- 已排除：Windows 凭据管理器（`cmdkey /list` 无 Trae 相关条目）。

## 4. 可行性开放项（Phase 0：登录态载体定位）

> ✅ **Phase 0 已于 2026-09-06 真机完成，方案确认可行，不降级。**
>
> 实测过程：账号 A 完全退出 → `snap 1`（109952 文件）→ 验证码登录账号 B →
> 完全退出 → `snap 2`（109951 文件）→ `diff 1` 得 **41 个变化文件**。
>
> 判读结论：
> - 41 个变化中绝大多数为运行噪声：`monitor\parfait\*`（时间戳遥测）、
>   `ModularData\*`（日志/会话 DB）、`ahanet\*`/`aha\*`、`solo-lite\thumbnail-assets\*`、
>   `*.LOG`/`LOG.old`、`QuotaManager`、`languagepacks.json` 等。
> - 登录态载体集中于 **6 个指纹条目（其中 3 个为目录）**，已写入
>   `%APPDATA%\TraeSwitch\settings.json` 的 `Fingerprint`：
>   `Local Storage\leveldb`（目录）、`Partitions\trae-webview\Local Storage\leveldb`（目录，
>   trae-webview 为网页授权分区，token 最可能落点）、`Session Storage`（目录）、
>   `Local Storage\config.db`、`Network\Network Persistent State`、`User\globalStorage\storage.json`。
> - ⚠️ **指纹采用目录级而非单文件**：LevelDB 的 `*.log`/`*.ldb` 序号会随写入滚动，
>   Phase 0 观察到的 `000588.log`/`000237.log` 等固定序号下一次切号并不相同；
>   因此以「目录」为最小备份单位，恢复时先整删目标再整树写回，避免孤儿文件。
> - `machineid`、`Local State`、`Network\Cookies*` 均未变化 → 登录态不在这些位置。
> - 对应开放项 1、2：载体为"每账号一小撮目录/文件、其余共享"，
>   冷切换只需替换上述少量载体，无需整目录对拷。
> - 对应开放项 3（同机多账号风控）：已进入 2 账号 Pilot（≥1 周）；
>   对应开放项 4（`--user-data-dir` 参数）仍未验证，保持开放。
>
> ✅ **目录级建档与免验证码切换已于 2026-09-06 双账号真机验证通过。**
>
> 建档状态（`%LOCALAPPDATA%\TraeSwitch\vault\`）：
> - `用户0612021494`（账号 A，主用，186 开头手机号）：37 个文件，目录结构完整；
> - `用户61249542048`（账号 B，测试，139 开头手机号）：32 个文件，目录结构完整；
> - 两者 `meta.json` 均含逐文件 SHA-256；B 的旧版「单文件级」残留备份已被目录级重做覆盖。
> - `settings.json` 的 `Accounts` 已登记两个账号。
>
> 切换实测：A → B 与 B → A 冷切换均**免手机验证码**直接进入目标账号。
> 说明目录级载体备份/整树恢复链路可靠（LevelDB 滚动日志无孤儿文件问题）。

切换是否成立取决于"登录态载体"能否被整份备份并在账号间替换。**Phase 0 的目标是定位载体**，
方法为"切号前后文件差异对比"。由于实验需要完全退出客户端、而用户正用该客户端与本工具对话，
Phase 0 顺延到用户某次"本来就准备切号/结束对话"时执行（一次性只读脚本，约 2 分钟出结论）。

> 若 Phase 0 证明载体不可整份替换（例如 token 与设备指纹强绑定、替换后立即被服务端吊销），
> 则本工具降级为"半自动引导"：只负责按账号名切换客户端数据目录并提示重新登录，仍优于手输 OTP 的次数不可承诺。

## 5. 组件与数据流

### 5.1 CarrierProfiler（载体学习器）

- 首次建档引导：用户在**已登录账号 X** 状态下触发"学习当前账号"。
  工具对载体候选范围做文件哈希基线；用户切到账号 Y 后再次触发，diff 出"随账号变化的文件集合"，
  记为 `Fingerprint`。
- Fingerprint 对同一客户端安装全局有效：学习一次（至少覆盖 2 个账号的一次切换），
  后续所有账号建档复用同一指纹，无需重复学习。
- 指纹只记录路径与哈希，不读取/保存文件内容。

### 5.2 VaultService（登录态备份库）

- 备份目录：`%LOCALAPPDATA%\TraeSwitch\vault\<账号名>\`。
- 备份内容：按 Fingerprint 逐文件**原样字节复制**（不解密）。
- 元数据：账号显示名、备份时间、每文件路径+长度+SHA-256、对应客户端版本。
- 完整性：切换前对 vault 内文件做哈希校验；若与客户端当前文件不一致（客户端曾改写过该载体）
  则提示该账号需"重新登录并更新备份"。
- 目录权限：仅当前 Windows 用户可读写；不进入任何 git/云同步目录。

### 5.3 SwitcherService（冷切换执行器）

切换流程（目标账号为 T，当前为 S）：

1. 保存当前态快照（若不存在 S 的备份则先自动建档，保证可回滚）。
2. 结束 `TRAE SOLO CN` 全部进程（含托盘驻留）；等待进程退出；超时/失败则中止并提示手动退出。
3. 将 T 的 vault 文件写回 Fingerprint 对应路径（覆盖）。
4. 重新拉起客户端可执行文件。
5. 完成校验：进程存活且窗口标题恢复为 TraeWork CN；登录是否真正生效以用户可见界面为准，
   不做 UI 强断言。

执行顺序细节、回滚逻辑与失败提示在实现计划中细化。

### 5.4 主界面（WinForms）

- 账号列表（含当前使用账号标识、最近备份时间、完整性状态）。
- 操作：学习/建档、一键切换、更新备份、删除账号、vault 完整性校验。
- 首次运行引导文案：工具仅在本机备份各账号登录态，用于免验证码冷切换；不读取对话内容。

## 6. 错误处理与恢复

- 客户端进程无法结束 / 载体文件被占用：中止切换，提示手动退出后重试。
- 写回前先落"当前态快照"，写回后任何一步失败可一键回滚到快照。
- 切换后目标账号 token 过期/被吊销（登录态失效）：提示"该账号需重新登录一次并更新备份"。
- vault 校验失败（哈希不匹配）：提示重新登录并更新该账号备份。
- 客户端升级可能改变载体布局：Fingerprint 校验发现路径集变化时，提示重新学习。

## 7. 测试策略

- 纯逻辑单测：Fingerprint diff、vault 备份/恢复/哈希校验/回滚、进程命令构造、账号元数据管理。
- 载体操作抽成薄接口；Phase 0 定位完成前用"假载体"（临时目录 + 假文件）跑通全流程。
- Phase 0 定位后接真实载体做 Pilot：用你自己的 2 个账号试运行 ≥ 1 周，
  确认切换稳定、无风控告警后再考虑给 3-4 账号的其他用户使用。

## 8. 风险与合规

- 多账号/会话复制属于用户自用便利需求，但有被服务端视为异常的风控风险（参考 9074）；
  工具不伪造请求、不加密对抗、不上传任何数据，降低被误判概率。
- 若账号被服务端要求重新验证，工具只做提示与引导，不尝试绕过。
- vault 内为真实登录态字节，属高敏数据：仅本机、仅当前用户、不上传、不写日志内容。
